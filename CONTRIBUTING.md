# Contributing

Thanks for your interest in improving this project.

## Ground rules

- Keep changes focused: one concern per pull request.
- Follow the existing code style (lint/typecheck must pass).
- Add or update tests for behavior changes.
- Never commit secrets, `.env` files, or credentials.
- By contributing, you agree your work is released under the repository's license (MIT unless stated otherwise).

## Workflow

1. Fork the repository and create a branch from `main` (or `master`).
2. Make your changes with clear commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
3. Run the local checks (lint, typecheck, tests) before opening a PR.
4. Open a pull request describing the problem and the solution.
5. Respond to review feedback.

## Issues

- Bug reports: include steps to reproduce, expected vs actual behavior, and environment details.
- Feature ideas: open an issue first to discuss scope before large PRs.
- Security issues: see [SECURITY.md](SECURITY.md) — do not open public issues.
